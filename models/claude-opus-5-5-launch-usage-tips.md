# Claude Opus 5.5 출시 — Fable 5.1급 성능을 40% 저렴하게, 제대로 쓰는 법까지

> 한 줄 요약: Anthropic의 Opus 5.5가 Fable 5.1에 근접한 성능을 이전 Opus 5보다 40% 낮은 비용으로 제공하며, 공식 블로그와 실험 결과로 "완료 기준 명시 + Low로 개발, High로 검증"이라는 활용법이 정리됐습니다.

## 핵심 요약
- **가성비 플래그십**: Fable 5.1과 동등한 성능, 실행 비용은 Opus 5 대비 **약 40% 절감**
- **에이전트 코딩은 Fable 5.1 이상**: 일부 벤치마크에서는 상위 모델을 앞섰고, Artificial Analysis 종합 점수 **1위**
- **3D·영상·게임 제작에 강점**: Three.js, Blender, 픽셀 아트, 영상 편집, 게임 프로토타입까지 한 번에 생성
- **공식 프롬프팅 팁**: 완료 기준·중단 조건을 명확히, "깊이 생각해" 같은 문구는 이제 불필요
- **추론 강도(Effort) 전략**: Low로 가볍게 구현·반복 → 최종 검증에만 High, Max는 토큰 낭비 주의

## 본문

### 성능과 가격

| 항목 | 내용 |
|------|------|
| 성능 수준 | Fable 5.1과 동등 수준 |
| 비용 | 이전 Opus 5 대비 **약 40% 저렴** |
| 에이전트 코딩 | Fable 5.1보다 **높은 점수** |
| GDPval (실무 업무 평가) | 높은 점수 기록 |
| Artificial Analysis 종합 | **1위** |

> **GDPval**: 실제 직업군의 업무(보고서, 분석, 문서 작성 등)를 AI가 얼마나 잘 수행하는지 측정하는 OpenAI의 평가 지표입니다.

정리하면 "가격은 내려갔는데 최상위 모델에 거의 도달한" 모델입니다. 대부분의 작업을 Opus 5.5로 처리해도 충분한 가치를 얻을 수 있습니다.

| 게임 | 언리얼 엔진 기반 게임 제작 |

#### 한 줄 프롬프트로 만든 "젤다: 브레스 오브 더 와일드"

영상 제작자가 직접 한 줄 프롬프트로 젤다 스타일 게임을 만들어 봤습니다.

- "눈을 떠라"로 시작하는 오프닝과 스토리 자동 생성
- 검 휘두르기, 활 조준·발사
- 오브젝트 활성화 기능
- **등반 시 스태미나 게이지 소모 → 회복** 시스템까지 구현

Blender 같은 도구와 결합하면 더 높은 품질도 가능하다고 합니다.

#### Opus + HyperFrames + Gemini TTS로 영상 자동 제작

HyperFrames(코드 기반 영상 제작 도구)와 새로 나온 Gemini TTS를 결합하면 **감정이 섞인 AI 내레이션 + 애니메이션 영상**을 거의 한 줄 요청으로 만들 수 있습니다. 영상 편집 용도로 Opus를 활용해 볼 만합니다.

### 공식 블로그의 Opus 5.5 활용 팁

| 팁 | 설명 |
|----|------|
| 완료 기준·중단 조건 명시 | "어디까지 하면 끝인지", "언제 멈출지"를 분명히 적기 |
| 장기 작업은 진행 보고·검증 요구 | 중간 진행 상황과 검증 결과를 보고하게 하기 |
| 처음부터 전체 업무 위임 | 잘게 쪼개 주기보다 전체 맥락을 한 번에 제공 |
| "깊이 생각해" 문구 삭제 | 모델이 스스로 추론 깊이를 판단 |
| 큰 코드 작업은 분할·검증·리뷰 | 원본 파일을 함께 제공 |

전반적으로 **AI가 충분히 똑똑해져서 예전의 프롬프트 요령들이 필요 없어지는 방향**으로 가고 있습니다.

### 추론 강도(Effort)는 언제 올려야 할까

Terminal-Bench 3.0으로 여러 실험을 해 본 결과를 정리한 글이 공개됐습니다. 추론 강도를 높일수록 토큰을 더 많이 쓰기 때문에 **상황별 선택**이 중요합니다.

| 강도 | 적합한 작업 | 비고 |
|------|------------|------|
| **Low** | 기본 로깅, 간단한 그래프 생성 | 대부분의 개발 반복에 충분 |
| **Medium** | 기능 추가 | |
| **High** | 최종 검증 | |
| **Max** | 사소한 세부 기능까지 AI에게 맡길 때 | 한 작업에 **67분** 소요, 알아서 기능을 과하게 추가 |

#### 추천 워크플로우

```
1. Claude에게 인터뷰를 받으며 명세서(Spec) 작성
2. Low로 가볍게 구현
3. 결과 검토 → 반복 수정 (Low 유지)
4. 최종 검증 테스트에만 High 사용
```

처음부터 Max를 쓰면 요청하지 않은 세부 기능까지 추가하면서 **토큰을 낭비**하게 됩니다.

## 실전 활용 / 팁
- **기본 모델로 Opus 5.5**: 비용 대비 성능이 가장 좋은 선택지이므로 일상 작업의 기본값으로 두세요
- **프롬프트에 "완료 조건" 한 줄 추가**: 예) "테스트가 모두 통과하고 README가 갱신되면 종료"
- **Effort는 Low부터**: 개발 단계는 Low, 배포 직전 검증만 High로 올리면 토큰을 크게 아낄 수 있습니다
- **크리에이티브 실험**: Three.js 3D 장면, 픽셀 아트 애니메이션, 게임 프로토타입을 한 줄 프롬프트로 시도해 보세요
