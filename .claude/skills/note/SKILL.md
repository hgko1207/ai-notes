# AI 노트 작성 스킬

사용자가 제공한 소스를 읽고 **확인한 사실**과 **우리에게 적용할 점**을 노트로 남긴다. 기준은 프로젝트 CLAUDE.md의 "쓰는 것 / 쓰지 않는 것"을 따른다. 소식만 옮기는 요약과 주간 뉴스 총정리는 쓰지 않는다.

적용 대상: team-ai-kit, cc-checkup, ai-setup-service(AI 코딩 팀 세팅 사업), 개인 프로젝트 (모두 `D:\project\Coding\` 아래).

## 실행 절차

### 1단계: 소스 분석
- 제공된 URL이나 텍스트를 깊이 분석 (URL이면 WebFetch로 가져온다. 못 읽으면 못 읽었다고 말하고 캡처나 본문을 요청한다)
- 핵심 주장, 숫자, 인사이트 추출
- 원글이 자기 제품·강의 홍보를 섞었는지 본다

### 2단계: 사실 확인
- 숫자·가격·정책·제품 동작처럼 나중에 근거로 쓸 주장을 골라 공식 문서나 원 저장소에서 직접 확인한다.
- 상태를 셋 중 하나로 정한다: **공식 확인** / **출처만** / **확인 못 함**. 확인 못 한 것을 사실처럼 쓰지 않는다.

### 3단계: 적용 판단
- 적용 대상의 현재 코드·문서를 열어 보고 바꿀 점을 찾는다. 추측으로 채우지 않는다.
- 대상별로 할 일과 상태(**적용함** / **검토 중** / **안 함**+이유)를 정한다.
- **적용할 점도, 근거로 남길 사실도 없으면 여기서 멈춘다.** 노트를 만들지 않고 "적용할 점이 없어 노트로 남기지 않음"과 이유를 답한다.

### 4단계: 분류 결정
- `models/` — AI 모델 관련 (특징, 비교, 활용법)
- `prompting/` — 프롬프트 엔지니어링 (기법, 템플릿)
- `tools/` — AI 도구/서비스 (리뷰, 활용 팁)
- `concepts/` — AI 핵심 개념 (기술 원리 설명)
- `trends/` — AI 업계 방향성 (주간 뉴스 정리는 쓰지 않음)
- `tutorials/` — 실습 가이드 (따라하기)
- `resources/` — 링크/논문/강의/공개 템플릿 모음

명확하면 바로 진행하고, 애매하면 사용자에게 확인한다.

### 5단계: 마크다운 작성
아래 템플릿을 따른다:

```markdown
# 제목 (핵심을 한 줄로)

> 한 줄 요약: 핵심 내용 한 문장

## 핵심 요약
- 바쁜 사람을 위한 3~5줄 핵심 포인트

## 본문
### 소제목 1
### 소제목 2
...

## 사실 확인
| 주장 | 상태 | 근거 |
|---|---|---|

## 적용할 점
| 대상 | 할 일 | 상태 |
|---|---|---|

## 마무리
- 핵심 정리, 개인 의견, 홍보가 섞였으면 그 사실 한 줄

---
**출처**: [원본 제목](URL)
**작성일**: YYYY-MM-DD
**태그**: 태그1, 태그2, 태그3
```

- "적용함"이면 커밋·버전·PR 번호를 함께 적는다 (예: 적용함 (team-ai-kit v0.4.0)).
- 나중에 실제로 적용하면 기존 노트의 "적용할 점" 표 상태를 고친다.

### 문체
- **존댓말(~입니다/합니다) 필수** — "~이다/~한다" 평서체 금지
- 친근하고 읽기 편한 톤 유지 (블로그 발행은 선택)

### 작성 원칙
1. **핵심 먼저** — 결론/요약을 글 상단에 (역피라미드)
2. **쉬운 말** — 전문 용어는 처음 등장 시 설명
3. **구조화** — 글머리 기호, 표, 번호 목록 적극 활용
4. **실용적** — "그래서 우리는 뭘 바꾸는데?"에 답하기
5. **적절한 길이** — 핵심 집중, 장황함 제거
6. **출처 명시** — 원본 링크와 사실 확인에 쓴 공식 문서 링크 모두 포함

### 6단계: 파일 생성
- 파일명: 소문자 영문, 하이픈 구분 (예: `claude-4-analysis.md`)
- 해당 폴더에 Write 도구로 저장
- 사용자에게 작성 완료 보고 (파일 경로 + 핵심 요약 + 적용할 점 표)
